# Zotero Fulltext Translator (Ollama)

用**本地 Ollama 大模型**翻译 Zotero 里的论文全文，并**尽可能保留原始版式**，输出中文 PDF。
目标环境：Zotero 7–10（bootstrap 插件模型）· Ollama · 可搜索文字 PDF。

```
Zotero 插件 (JS)                          Python 引擎 (PyMuPDF)
├ 设置面板 / 菜单 / 进度窗       ──cfg──▶  translate_pdf.py
├ 定位选中条目或当前阅读器里的 PDF           1 提取文字块(坐标/字号/颜色/公式)
├ 子进程调度、取消、错误提示     ◀─JSON行─  2 调 Ollama 批量翻译(缓存/校验/回退)
└ 把译文作为子附件导入并打开                 3 擦除原文 → 按原位置用中文字体重排 → 输出 PDF
```

为什么要 Python？在 Zotero 里（JS）几乎无法可靠地读取文字坐标并改写 PDF；PyMuPDF 可以。

---

## 1. 安装

### 1.1 Ollama 与模型
```bash
ollama serve            # 桌面版 Ollama 保持运行即可
ollama pull qwen3.5:4b  # 或任何你想用的模型，设置里填同名
```
### 1.2 Python 依赖（Python 3.9+）
```bash
pip install -r requirements.txt     # pymupdf + fonttools
```
> 插件会依次查找 PATH、常见安装目录（Windows: `%LOCALAPPDATA%\Programs\Python`、Anaconda 等；macOS: Homebrew）和 `py` 启动器，并试运行、优先选已装 PyMuPDF 的那个；找错或找不到就在设置里指定路径。
> `fonttools` 用于裁剪字体、抽取简体字面，缺失时输出文件会很大。

### 1.3 中文字体
准备一个含简体中文的 **.ttf / .otf**（推荐 `NotoSansSC-Regular.otf` 或思源宋体）。
`.ttc` 合集也可以（引擎会用 fonttools 自动抽出简体字面）。留空时会尝试系统常见字体。

### 1.4 安装插件
```bash
python tools/build_xpi.py           # 按 manifest 版本生成 dist/zotero-fulltext-translator-<version>.xpi
```
Zotero → 工具 → 插件 → 右上角齿轮 → **Install Plugin From File…** → 选择 xpi → 重启 Zotero。

### 1.5 配置并自检
Zotero → 设置 → **全文翻译 (Ollama)** → 填好地址/模型/字体 → 点 **「检测 Python / 字体 / Ollama / 模型」**，全部 ✓ 即可。

> **关于 `update_url`**：Zotero 要求 manifest 必须包含它，否则安装时报 `applications.zotero.update_url not provided`。
> 当前是占位地址（`example.invalid`），只影响自动更新检查（会静默失败），不影响使用。
> 自己托管后，把 manifest.json 里的地址和 `update.json` 一起改成真实链接即可。

## 2. 使用
* **条目右键** → 「翻译全文为中文 PDF（Ollama）」（可多选，逐篇排队）。
* 正在阅读器里看论文时：**工具 → 翻译当前论文全文（Ollama）**。
* 条目右键 → **并排查看原文与译文**：打开对应的原 PDF 和已导入的中文 PDF，并尝试将两个阅读器窗口左右排列。此功能要求译文已作为 Zotero 子附件导入。
* 条目右键 → **生成论文总结到笔记**：用设置中的 Ollama 模型总结 PDF，并将结构化中文总结保存为该论文的 Zotero 子笔记；长论文会分块分析后再整合。阅读器打开论文时也可从「工具」菜单触发。
* 进行中可在 **工具 → 取消正在进行的全文翻译** 中止；再次运行会命中缓存，从上次进度继续（缓存按 模型+原文 命中）。
* 结果默认作为子附件「[中文] 标题」导入并打开；输出目录里同时保留文件。

> 论文总结会将 PDF 中提取出的文字发送到设置中配置的 Ollama 地址。使用远程 Ollama 服务时，请确认论文内容可以发送到该服务。

## 3. 设置项
| 设置 | 说明 |
|---|---|
| Ollama 服务地址 / 模型名称 | 如 `http://127.0.0.1:11434`、`qwen3.5:4b`（已关闭 think 以提速） |
| 中文字体 / 粗体字体 | 粗体字体用于标题等粗体段落，可留空 |
| PDF 输出目录 | 留空 = `<Zotero数据目录>/translated-pdfs` |
| 结果处理 | 导入为子附件 / 链接附件 / 只存文件 |
| 翻译模式 | **原位替换**；**双语对照**（原文页+译文页交替） |
| 擦除背景 | 自动取色（保留彩色底）/ 纯白 / 不填充 |
| 最小字号比例 | 译文放不下时先收紧行距，再整栏统一逐步缩小字号，最低到原字号的该比例（默认 50%）。仍放不下会计入「仍溢出」，可调低该值 |
| 翻译表格单元格 | 表头/行标签翻译；纯数字、全大写缩写、未翻译的单元格**不会被擦除**，数据不丢 |
| 统一正文字号与缩放 | 全文按字符数加权取**主导字号**作正文字号：与其相差≤10% 的段落、≥3 行的长段落（字号取值异常也一样）统一按它排；放不下时**全文共用同一档缩放**（取第 90 百分位），只有个别放不下的栏才单独再缩。标题、小号脚注保持原有层级 |
| 诊断文件 | 开启后在译文旁生成 `.debug.json`（每个段落的坐标/字号/行数/原文/译文、被去重的区域），反馈排版问题时附上 |
| 保护行内公式 | 公式换成 `[[n]]` 占位符，译后原样放回 |
| 跳过参考文献 / 页眉页脚 / 翻译图表标题 | 见设置面板 |
| 页码范围 | 如 `1-3,5`，调试排版时很有用 |
| 补充提示词 | 术语表、风格要求，会拼进系统提示 |

## 4. 版式重建怎么做的
1. `page.get_text("dict")` 取每行每个 span 的字号、颜色、字体、坐标；按行距/字号/短行收尾切成**自然段**。
2. 数学字体(CMMI/CMSY/Symbol…)、上下标、希腊符号 → 公式占位符；断词连字符还原；旋转文字(arXiv 水印)与纯公式块跳过。
2a. **拉伸行合并**：两端对齐的行若词间距被拉得很大、被拆成几个短碎片，只要整行与上/下相邻行左右两端齐平、且各列不对齐(不是表格)，就合并回一行（限同一文字块内，避免两栏误并）。缺失的词间空格按字符间隙补回。
2b. 行内按**大水平间隙**切成单元格；同一水平带上左右并列的短文本视为表格单元格，各自独立翻译、独立排版（可向右借空白），不与上下文合并。
   段落是否结束看「句末标点 + 行偏短/下一行缩进」，右侧参差不齐的文本不会被切碎。
3. 批量 JSON 翻译（带 schema），失败/缺项/未翻译自动**逐条回退**；占位符丢失会补回段末。
4. 取原文背景色 → `redact` 只删文字（不动图片与矢量图）→ 用中文字体**原位**写回：
   中英混排与公式分字体量宽、标点避头尾、真正居中的标题保持居中；
   **同一栏上下相邻的段落一起排**：前一段变长就把后一段往下推（不与相邻段落重叠），到栏底/下一个图表前仍放不下，才整栏统一缩小字号。
4b. 同一块文字被提取多次（叠印、隐藏 OCR 文字层）时只保留文字更长的一份，另一份只擦除不重画。
5. 字体裁剪到仅含用到的字符，整本几百 KB。

## 5. 已知限制（请先看）
* 仅处理**有文字层**的 PDF。扫描件会报 `E_NO_TEXT`，需先 `ocrmypdf`。
* 复杂多栏、跨栏/跨页段落按"PDF 内部块"处理，不会跨块合并；极端排版可能出现个别段落溢出（面板与结果里会统计"仍溢出"数量）。
* 行内公式用占位符保留，字体用中文字体/Helvetica 绘制，**不会 100% 还原 LaTeX 外观**；复杂的独立公式块保持原样不动。
* 小模型（4B）对长段落、术语一致性有限，可在"补充提示词"里加术语表；换更大的模型质量更好。
* 译文放进原框的空间有限：汉字更"方"，所以可能比原文略小。

## 6. 排错
| 现象 | 处理 |
|---|---|
| 地址带 `/v1` | 无需处理：引擎会自动去掉末尾 `/v1`、`/api`，走 Ollama 原生接口 |
| `E_PYTHON` | 设置里指定 Python 路径；Windows 可填 `C:\Users\你\AppData\Local\Programs\Python\Python312\python.exe` |
| `E_NO_PYMUPDF` | 用**同一个 Python** 执行 `pip install pymupdf fonttools` |
| `E_OLLAMA_DOWN` | 启动 Ollama；地址是否带 `http://`；远程机器需 `OLLAMA_HOST=0.0.0.0` |
| `E_MODEL_MISSING` | `ollama pull <模型>` |
| `E_FONT` | 选一个含中文的 ttf/otf |
| 文件很大 | 安装 fonttools |
| 字形像日文 | 不要用 Noto CJK 的 ttc 直接当字体之外的东西；装 fonttools（会自动选 SC 字面）或改用 SC 的 otf |
| 想看日志 | Zotero → 帮助 → 调试输出日志 → 查看，搜索 `[FTT]` |

脱离 Zotero 调试引擎：
```bash
python engine/translate_pdf.py --config job.json --check
python engine/translate_pdf.py --config job.json
```
`tools/mock_ollama.py` 是一个假 Ollama 服务，`tools/make_sample_pdf.py` 生成测试 PDF，可不装模型验证整条流水线。
